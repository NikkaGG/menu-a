# Админ-панель: UI/UX и обслуживание

## Архитектура и границы изменений

Панель остаётся статическим приложением: `admin.html`, `admin.css`, `admin.js`. React и новые зависимости не добавлены. Сохранены разделы «Обзор», «Аналитика» (пять вкладок), «Блюда», «Категории», «Контент сайта», существующие поля редакторов, загрузка изображений, история и планирование цен, массовые операции и RPC Supabase. Данные аналитики не трактуются как подтверждённые заказы; сравнение с предыдущим периодом не выдумывается.

## Результаты аудита и решения

- Неясная иерархия и неоднородные действия → единые заголовки, контекст раздела, основное действие, фильтры и рабочий контент.
- Слабая читаемость → локальные SF Pro Text (400/500/700) с системным fallback, основной размер 15.5px, контрастные вторичные подписи, табличные цифры.
- Бинарная тема и ошибка инициализации `querySelector(...).forEach` → Light / Dark / System, корректная коллекция элементов, сохранение предпочтения и реакция на изменения системной темы.
- Перегруженные строки → отдельное редактирование и компактное меню дополнительных действий; сортировка, поиск и пагинация остаются клиентскими представлениями существующего каталога.
- Недоступные большие окна → нативные `dialog`, редактор блюда в боковой панели, сфокусированные небольшие подтверждения.
- Недостаточная обратная связь → локальные ошибки полей, сводка ошибок, сохранение ввода при ошибке сервера, skeleton при первой загрузке, повторная загрузка без удаления уже показанных данных.
- Перетаскивание без клавиатурной альтернативы → действия перемещения выше/ниже с тем же RPC изменения порядка.

## Дизайн-система

Основа текущего оформления: Apple/macOS-inspired workspace с рекомендациями UI UX Pro Max для прозрачных материалов. Паттерны shadcn адаптированы к нативному HTML, без внедрения React-компонентов в статический сайт. Семантические CSS tokens задают поверхности, текст, границы, поля, основной акцент, ошибки, focus и sidebar. Светлая серебристая и тёмная графитовая палитры определены отдельно. Оранжевый акцент заменён синим: отдельные tokens для заполненных кнопок и текста/графиков обеспечивают читаемость в обеих темах. Полупрозрачные поверхности используют backdrop blur, тонкие границы и мягкие тени; фон не инвертируется.

Контрольная сетка: отступы 4/8px, плавающий sidebar 240px с внешним отступом 16px на desktop, отдельная скруглённая верхняя панель, ограниченная ширина содержимого. На мобильных устройствах — drawer, компактная верхняя панель с доступными темой и обновлением, KPI в две колонки, таблицы с собственным горизонтальным скроллом. Для анимаций учитывается `prefers-reduced-motion`; предусмотрены fallback без backdrop-filter, reduced transparency и forced colors.

Тема хранится в `localStorage['menu-admin-theme-v2']` как `light`, `dark` или `system`. Ранний скрипт в `<head>` определяет итоговую тему до отрисовки. Нативные элементы управления темой доступны на экране входа и в верхней панели.

## Семантика таблиц и операций

Выбор всех относится ко **всем найденным блюдам**, а не только текущей странице; счётчик массового действия показывает полный выбор. Поиск и фильтры не меняют данные. Ручная перестановка доступна в режиме «По порядку в меню»; ценовая/алфавитная сортировка не записывает порядок в базу. Скрытие категории предупреждает о скрытии её блюд. Массовая смена цен и отмена запланированной цены требуют подтверждения.

## Локальный запуск

Из корня проекта:

```sh
python -m http.server 8765
```

Открыть `http://localhost:8765/admin.html`. Это только статический сервер: Vercel `/api/branding` и серверные функции он не исполняет. Для полного окружения нужны соответствующий сервер и действующая авторизация Supabase.

## Проверка без изменения рабочего меню

При редизайне браузерные сценарии выполнялись с изолированными ответами RPC: каталог из `ref-products-dom.json`, синтетическая аналитика только для проверки представлений. Подмена запросов существует исключительно в проверочном браузере; в приложении нет демонстрационных данных, обхода авторизации или фальшивого успешного сохранения.

Контрольные размеры: 375, 768, 1024 и 1440px. Проверять обе темы, системную тему и её сохранение, каждый раздел/вкладку, таблицу и её дополнительные действия, выбор и пагинацию, inline validation, ошибки сервера и повторную загрузку, редакторы, подтверждения, Escape/focus и мобильную навигацию. При проверке реальных сохранений использовать тестовую среду: админ-панель отправляет изменения непосредственно в настроенный Supabase.

Браузерная проверка представлений и исходящих payload не заменяет интеграционную проверку реальной базы, авторизации, хранения файлов и публичного меню. Production-данные в ходе локального UI-редизайна не изменялись.

### Зафиксированные результаты локальной проверки

- `node --check admin.js` — успешно.
- 40 сочетаний (5 разделов × 4 ширины × 2 темы) — ширина документа совпала с шириной viewport, горизонтального переполнения страницы не обнаружено.
- Все пять вкладок аналитики открываются; поиск, ценовая сортировка, пагинация и выбор всех найденных блюд проверены на каталоге из 61 позиции.
- В браузере проверены отправляемые payload для сохранения блюда/категории/контента, переключения видимости, копирования, перестановки, массовых цен и планирования/отмены цены. Проверка выполнялась на перехваченных RPC, а не на рабочей базе.
- Проверены ошибки сохранения с сохранением ввода, повторная загрузка, inline validation, подтверждения, возврат focus после вложенного окна и обновления таблицы, закрытие всех окон при истечении сессии, обратная связь загрузки изображения.
- Пустое меню направляет пользователя сначала к созданию категории; обе кнопки пустых состояний работают независимо, без дублирующихся ID.
- Light / Dark сохраняются после reload; System реагирует на изменение системной темы. Для текущих Apple tokens измерены: вторичный текст на светлом базовом фоне — 5.22:1, на тёмной поверхности карточки — 5.95:1; белый текст основной кнопки — 5.33:1 в Light и 4.70:1 в Dark. Placeholder использует контрастный вторичный цвет без снижения opacity. Это проверки указанных цветовых пар, а не сертификация всех сочетаний прозрачных поверхностей.
- На проверенном desktop-сценарии высота панелей популярных блюд и состояния меню оставалась 497px до и после первой загрузки (skeleton → данные).
- После финальной загрузки браузер не зарегистрировал runtime errors. Это не является полной сертификацией WCAG или проверкой реального backend.
- После Apple-переработки повторно пройдены 40 сочетаний разделов, ширин и тем через реальные элементы навигации: нет горизонтального переполнения или обрезанной кнопки обновления, закрытый мобильный sidebar недоступен фокусу, скрытый экран входа не занимает место в рабочей панели.
- В мобильном drawer исправлено наложение backdrop поверх навигации: общие свойства sidebar/topbar определены вне desktop-only breakpoint. Тень закрытого drawer отключена; на узких экранах статус сохранения остаётся live-region без занятия места в верхней панели.
- В обеих темах визуально проверены dashboard, аналитика, каталог и меню действий, категории, настройки, редакторы, подтверждения и экран входа; повторно проверены поиск, массовый выбор и отмена подтверждения. При этой Apple-переработке бизнес-логика и RPC не менялись.
